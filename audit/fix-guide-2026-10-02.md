# Fix guide for an AI agent — audit 2026-10-02

How to fix each open finding in `full-audit-2026-10-02.md`, from critical to
low. Read the finding there first (it has the evidence). This guide says
**when** to do it, **where to look**, **what to change**, **what to watch
out for**, and **how to prove it is fixed**.

F-88 and F-98 are already fixed (with Role Management, API Management and
Admin Settings now main-admin only). Everything below is open.

## Rules for every fix

- One finding per commit (two small LOW ones may share). Commit message
  names the ID, e.g. `Fix F-89: ...`.
- Follow `CLAUDE.md`: `AUDIT_LOG.md` entry, `GUIDE.md` when admins notice
  the change, and the checks before pushing:
  ```bash
  ruff check backend_fastapi
  python -m pytest backend_fastapi/tests -q -p no:warnings
  npx tsc --noEmit && npx vitest run && npx vite build
  ```
- Every fix adds a test that **fails before** the fix and passes after.
  Write the test first and watch it fail.
- Never weaken a gate to make a test pass; never skip a test.
- House rules that limit the fixes: Secret Vault / Admin Settings / API
  Management / Scraper AI / branding / donations / roles are main-admin
  only; bookmarks and history stay in the browser; translation runs on the
  server.
- In mark-up-free terms for the owner: say what changed for readers and
  admins, not just the code.

## CRITICAL

### F-89 — Provider secrets readable without signing in

**When:** immediately. After deploying, tell the owner to replace (rotate)
every key that was ever put in a custom provider header.

**Where to look**
- `backend_fastapi/app/services/provider_registry.py` → `_masked_payload`
  (returns `"headers": headers`, values included) and `to_public_payload`.
- `backend_fastapi/app/api/routers/config.py` → `list_providers`
  (`GET /config/providers`, no auth).
- Who uses it: `src/services/api.js` → `config.providers` (grep the callers
  to see which fields the UI really needs).

**What to change**
1. In `_masked_payload`, return header **names only**
   (`sorted(headers.keys())`), never values. Same for anything else that
   builds a public/masked view.
2. Decide what the public endpoint is for. Readers only need to know which
   services exist (e.g. `availableServices`, local OCR on/off). Return only
   that; drop `apiUrl`, `model`, masked key and headers from the public
   payload.
3. Put the full masked view behind `require_main_admin_user` (a separate
   admin endpoint if the admin UI needs it).
4. Check the admin save response (`PUT /admin/system-providers`) too: it
   echoes header values back; main-admin only, but still mask them.

**Watch out for**
- The same handler is served at `/config/providers`, `/api/config/providers`
  and `/api/v1/config/providers` (aliases). Test all three or test the
  route function.
- Frontend code reading `providers.<service>.headers` must not break: grep
  `src/` for `.headers` and `apiUrl` usage before removing fields.
- The scraper AI record is also `is_system`: make sure it never appears.

**Prove it**
- Test: main admin saves a provider with header `api-key: SECRET`; an
  anonymous `GET /api/v1/config/providers` must not contain `SECRET`, the
  URL, or the key tail. Same for the two alias paths.
- Test: the admin endpoint still shows header names.

### F-93 — Page translation blocks the API worker

**When:** this week; it is the main cause of freezes under load.

**Where to look**
- `backend_fastapi/app/api/routers/processing.py` → `process_chapter_page`
  (`async def`, calls `cps.process_page(...)` directly, ~line 295).
- `backend_fastapi/app/services/chapter_processing_service.py:178`
  (`process_page`, sync: downloads image, OCR, HTTP translation).
- Same pattern to check in `routers/ocr.py` (`translate_overlay`,
  `translate_upload`, `extract_text`).
- Existing helper: `backend_fastapi/app/utils/bounded_threadpool.py`
  (`run_in_db_threadpool`).

**What to change** (pick one, start with A)
- **A (small, safe):** move the blocking part into a thread:
  `result = await run_in_threadpool(lambda: cps.process_page(...))`
  (or the project's bounded pool). The DB session used inside must be
  created and closed **inside** the thread function, not shared with the
  request's session across threads.
- **B (best for small servers):** queue it to the existing
  `celery_worker_ocr` queue; the endpoint returns cached regions
  immediately, or `202` + a task id the reader polls. `ReaderOverlay.js`
  must then poll.

**Watch out for**
- SQLAlchemy sessions are not thread-safe: don't pass the request `db`
  into the thread while also using it in the request.
- The limiter/ceiling calls (`platform_ceiling_service.check_and_increment`)
  are async; keep them on the event loop before the hop.
- Keep the `used_fallback` notice and provider success/failure recording.
- Bound concurrency (bounded pool or Celery) so 20 readers don't start 20
  OCR jobs on a 1-CPU box.

**Prove it**
- Test: patch `process_page` to sleep 1 s; fire it and, concurrently,
  `GET /api/v1/version`; the version call must return in well under 1 s.
- Existing processing tests stay green.

## MEDIUM

### F-96 — Default deployment needs ~2.5 GB RAM, never recycles workers

**When:** this week, together with F-93 (both decide whether a small server
survives).

**Where to look**
- `docker-compose.yml` (8 `celery_worker_*` services, beat, backend).
- `backend_fastapi/deployment/gunicorn.conf.py` (`2 × CPU + 1` workers).
- `backend_fastapi/app/core/celery_app.py` (no
  `worker_max_memory_per_child` / `worker_max_tasks_per_child`).
- `backend_fastapi/app/core/db.py` (pool 20 + overflow 10 per process).
- `backend_fastapi/scripts/start_celery_worker.sh`.

**What to change**
- Add `worker_max_tasks_per_child` (e.g. 200) and
  `worker_max_memory_per_child` (e.g. 300 MB, in KB) to `celery_app.py`,
  overridable by env.
- Add a documented **small-server profile** (e.g.
  `docker-compose.small.yml` override or a Compose profile): one Celery
  worker consuming every queue, `--concurrency 1`; `GUNICORN_WORKERS=2`;
  `SQLALCHEMY_POOL_SIZE=5`, `SQLALCHEMY_MAX_OVERFLOW=5`; Redis
  `maxmemory 128mb` + `maxmemory-policy allkeys-lru`; Postgres
  `shared_buffers=128MB`, `max_connections=40`.
- Document it in `GUIDE.md` (install section + checklist).

**Watch out for**
- The queue names each worker consumes: the combined worker must list all
  of them (`-Q scrape,compress,ocr,translation,email,maintenance,notifications,...`
  — read the real names from compose).
- Beat must still run exactly once.
- `.env.example` documents pool sizing — keep it consistent.

**Prove it**
- `docker compose -f docker-compose.yml -f docker-compose.small.yml config`
  is valid; on a 1 GB VM all containers stay up (`docker stats`).
- A test that `celery_app.conf.worker_max_tasks_per_child` is set.

### F-94 — Blocking database calls inside async handlers

**When:** next; do the reader path first.

**Where to look**
- Start with `routers/manga.py` → `get_chapter_content`,
  `get_chapter_list`; then `reader.py`, `comments.py`, `auth.py`,
  `site_admin.py`.
- Finding a full list: AST scan for `async def` route functions that take a
  `Session` and call it without a thread hop (the audit lists counts per
  file).

**What to change**
- If the handler awaits nothing important: change `async def` → `def`
  (FastAPI then runs it in its thread pool).
- If it must await (rate limiter, Redis cache): keep `async def` and move
  the DB part into a function run via `run_in_db_threadpool` with its own
  session.

**Watch out for**
- Don't convert handlers that `await` limiters to `def` — the await would
  break. Split instead.
- Response caching decorators may need the function to stay async.
- One router per commit; run its tests each time.

**Prove it**
- Existing route tests green; a small concurrency test like F-93's on
  `get_chapter_content` with a slow DB stub.

## Feature (not a finding): translation bubbles that follow the bubble's shape

**When:** after F-89, F-91 and F-93 (it adds work to the translation path,
so that path should be off the event loop first).

**Where to look**
- `backend_fastapi/app/services/region_classifier.py` →
  `sample_background` (already samples the bubble fill colour).
- `backend_fastapi/app/services/ocr_normalize.py:108` (where regions get
  styling).
- `src/components/ReaderOverlay.js` (maps region fields) and
  `src/components/OverlayBox.js` (draws the box, shrink-to-fit).
- Reader settings: `src/settings/ReadingSettings.tsx`,
  `user_settings` router/schema for a new setting.

**What to build**
1. Server, Pillow only (no numpy/OpenCV, keep it light): from each text
   box's centre cast ~48 rays outward over pixels close to the sampled fill
   colour until a dark outline is hit (cap the distance at ~2.5× the text
   box). The hit points = bubble outline. Compute the outline's bounding
   box, a simplified polygon (≤ 32 points, coordinates as fractions of that
   box), and a shape class: `rectangle` (polygon area ≥ 93 % of its box),
   `ellipse` (≈ 70-85 %, covers circles and egg shapes), else `freeform`.
   If `background_clean` is false or rays don't close, return no bubble.
2. API: add `bubble: {shape, box: {x,y,width,height}, polygon: [[x,y],...]}`
   per region; old clients ignore it. Cache with the page result.
3. Reader: when `bubble` exists, position the fill over `bubble.box` and
   clip it: `clip-path: ellipse(...)` for ellipses, square corners for
   rectangles, `clip-path: polygon(...)` for free-form; inset 2-3 px so the
   page's own outline stays visible. Put the text in the inscribed area
   (≈ 71 % of an ellipse's width/height, centred) and keep shrink-to-fit.
4. Setting "Bubble shape: match page / plain box" (default match page).

**Watch out for**
- Speed: a few thousand pixel reads per bubble; measure per-page time
  before/after and keep it small.
- Bubbles touching the page edge or merged with art → fall back to the box.
- Vertical Japanese text: the inscribed area is taller than wide; let
  shrink-to-fit handle it.

**Prove it**
- Unit tests on synthetic images drawn with Pillow: a white circle, an
  ellipse, a rectangle and an egg shape with black outlines and text →
  correct `shape` and a polygon close to the drawn outline; busy background
  → no bubble.
- Vitest: `OverlayBox` with an ellipse bubble renders `clip-path: ellipse`.
