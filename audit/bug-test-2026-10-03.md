# Whole-site bug test — 2026-10-03

Asked by the owner: "check if every function of our website is working
properly, are there hidden redundancies or hidden bugs; a bug test of the whole
website". Branch `claude/funny-gauss-k12tkr`. The change entry is in
[`../AUDIT_LOG.md`](../AUDIT_LOG.md).

## How it was tested

| What | How |
| --- | --- |
| Automated checks (baseline, before any change) | `ruff` clean; backend **1234 passed, 11 skipped**; `tsc` clean; frontend **59 passed**; `vite build` OK |
| The real site | API on **PostgreSQL 16** with all migrations, the web gateway on the **production build**, test series and chapters, a reader and an owner account (owner seat claimed, authenticator enrolled with real TOTP codes) |
| Clicked through in Chromium | As a guest with sign-in required **on** and **off**, as a reader, and as the owner: home, browse, series page, reader, bookmarks, settings, notifications, 404, and **all 16 admin pages**. Every console error, failed request and page error was recorded |
| Flows | E-mail sign-in link, complete profile, authenticator set-up, Site Functions switch, guest bookmark (saved in the browser by series ID), posting a comment, branding save |
| Schema | Tables and columns created by `alembic upgrade head` compared with the models, on PostgreSQL and on SQLite |
| Privacy | Every guest-reachable endpoint checked for e-mail, IP and user data |
| Redundancy | Every function in `src/services/api.js` checked for a caller |

All 16 admin pages loaded with no console errors and no failed requests. The
Site Functions switch works both ways, and with it off a guest can browse, read
and bookmark.

## Fixed in this branch

| # | Severity | Finding | Fix |
| --- | --- | --- | --- |
| BT-1 | owner rule | *Sign-in required* started on. The owner now wants it off at the start, switched on later | Default off (code, Site Functions, database default); migration `20261017_login_required_default_off` switches the existing site off. An unreadable setting keeps guests out |
| BT-2 | medium (privacy) | The comments API sent every author's masked e-mail (`r***r@example.test`) to anyone, guests included, and decrypted one e-mail per comment | Field removed from comments |
| BT-3 | medium | Every comment showed its author as "Reader" (`user_name` vs the API's `username`); likes never showed (`score` vs `like_count`); removed comments were blank; a failed post was silent | Fields fixed; removed/deleted comments say so; the error is shown and the text kept |
| BT-4 | medium | The site's branding: the navbar never loaded the saved name/logo; the footer preferred the admin's own browser copy and defaulted to another site's name (MGEKO.CC) and its Discord, X, Telegram and Reddit links. The footer editor and Admin Settings pre-filled the same, so saving could store them | Saved branding wins everywhere; no foreign names or links |
| BT-5 | medium (local testing) | An e-mail sign-in link was spent twice under React StrictMode (development). The second call got 401 and sent the newly signed-in person to `/login` | The page spends each link once |
| BT-6 | low | The reader page showed "Manga #7" instead of the series title (`chapter.manga.title` vs the API's `manga_title`) | Fixed |
| BT-7 | low | `favicon.ico`, `logo192.png`, `logo512.png` missing: 404 on every page; the service worker's `addAll` failed, so it never installed | Icons added; the install skips a missing file |
| BT-8 | low | Guests saw the notification bell, which polled every 20 s and got 401 forever | The bell shows for signed-in people only |

Each fix was checked again in the browser afterwards, and has a test. Final
run: backend **1237 passed, 11 skipped**; frontend **64 passed**.

## Found, not fixed (need a decision or a larger change)

| # | Finding | Suggestion |
| --- | --- | --- |
| BT-9 | **"New chapter" notifications reach nobody.** The scheduled check notifies readers with a server-side bookmark, but bookmarks live in the browser, so none exist. | Owner's choice: an opt-in "follow this series" saved on the server under the account ID, or drop the feature |
| BT-10 | **Unused server code:** `/bookmarks`, `/history`, `bookmarks/import`, the `read_history` table and `suggestion_service`; about 60 never-called functions in `src/services/api.js` | Remove in a clean-up PR (with a migration for the tables) |
| BT-11 | **Features with no page:** Community (emojis, realms, memes, ranks, pills), comment edit / vote / react / report / moderation, notification preferences | Build the pages, or hide the Community switch until there is one |
| BT-12 | The homepage header text an admin edits is saved only in that admin's browser | Store it with the site settings |
| BT-13 | With sign-in required on, the login page still asks for footer, support links and ad slots and gets 401 (noise only) | Skip those calls for guests while the switch is on |
| BT-14 | SQLite development database: PostgreSQL-only migrations leave out `settings`, `footer_settings`, `login_tokens`, `complaints` and some columns (maintenance mode can't be read there) | Use PostgreSQL locally (the install guides already do) |
| BT-15 | The rate limiter (300 requests a minute per address) is reached by about 30 quick page loads, because each full page load makes about 10 API calls | Fine for real visitors (normal clicks don't reload the page); keep in mind behind a proxy that hides visitors' addresses |

Not covered: real Google / Microsoft sign-in, real SMTP, real source sites for
scraping, OCR and translation providers (the sandbox can't reach them), and the
Docker image build.
